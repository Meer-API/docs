---
title: "Usage and billing periods"
description: "Check your credit balance, select a billing period and page through usage history."
---

`GET /v2/usage_stats` reports credit balances and usage for your account's billing periods. Usage is shared across all API keys for the account. Reporting is free and does not create a new billing period.

## Check your latest period

Without query parameters, the endpoint returns the most recent **stored** period. This may be a past period if no newer period has been created.

```bash
curl 'https://api.meerapi.com/v2/usage_stats' \
  --header 'Authorization: Bearer <YOUR_API_KEY>'
```

The response contains a `data` array, even when you request a single period:

```json
{
  "customer_name": "acme_corp",
  "data": [
    {
      "id": 123,
      "type": "monthly",
      "start_date": "2026-10-01T00:00:00Z",
      "end_date": "2026-11-01T00:00:00Z",
      "credit_limit": 10000,
      "credits_used": 900,
      "credits_remaining": 9100,
      "total_requests": 700,
      "by_country": [
        { "country": "US", "request_count": 500 },
        { "country": "AU", "request_count": 200 }
      ],
      "unallocated_usage": { "request_count": 0, "credits_used": 0 }
    }
  ],
  "next_cursor": null
}
```

`start_date` is inclusive and `end_date` is exclusive. Both are UTC timestamps. Billing periods can start partway through a calendar month.

An account with no stored periods receives `data: []` and `next_cursor: null`.

## Select periods

Request up to 100 periods per page with `num_billing_periods`. Results are ordered by start date and then ID, newest first.

```bash
curl --get 'https://api.meerapi.com/v2/usage_stats' \
  --header 'Authorization: Bearer <YOUR_API_KEY>' \
  --data-urlencode 'num_billing_periods=3'
```

When `next_cursor` is a string, copy it unchanged into the next request's `cursor` parameter. Keep using the same account and page size, and stop when `next_cursor` is `null`.

```bash
curl --get 'https://api.meerapi.com/v2/usage_stats' \
  --header 'Authorization: Bearer <YOUR_API_KEY>' \
  --data-urlencode 'num_billing_periods=3' \
  --data-urlencode 'cursor=<NEXT_CURSOR>'
```

To fetch one specific period, pass its `id` instead:

```bash
curl 'https://api.meerapi.com/v2/usage_stats?id=123' \
  --header 'Authorization: Bearer <YOUR_API_KEY>'
```

You can obtain IDs from a usage response or [list billing periods](/api-reference/usage/list-billing-periods) with `GET /periods`. That endpoint returns only `id`, `type`, `start_date` and `end_date` for each period, with the same `customer_name`, `data` and `next_cursor` envelope. Its page-size parameter is `limit` (default 20, maximum 100).

| Selection | Result |
| --- | --- |
| No parameters | Most recent stored period; page size defaults to 1. |
| `num_billing_periods=3` | Up to three periods, newest first. Valid page sizes are 1–100. |
| `cursor=...` | Next page of older periods for the same account. |
| `id=123` | One period in `data`, with `next_cursor: null`. |

Do not combine `id` with `num_billing_periods` or `cursor`. Invalid parameters, unsupported parameters such as `year`, and invalid cursors return `400`. An unknown period ID or an ID belonging to another account returns `404`.

## Read the balance and breakdown

| Field | Meaning |
| --- | --- |
| `credit_limit` | Credit limit recorded for the period. |
| `credits_used` | Credits used, including pending charges. |
| `credits_remaining` | `credit_limit - credits_used`; may be negative after a limit reduction. |
| `total_requests` | Charged requests, including pending charges. A request may use more than one credit. |
| `by_country` | Completed lookups with attributable detail, sorted by count descending and then country code. |
| `unallocated_usage` | Requests and credits included in the totals that cannot be assigned to dated billing-month detail. |

Refunds reduce usage in the original billing period. Pending charges and historical usage without dated detail can make the sum of `by_country[].request_count` smaller than `total_requests`. Use the period totals for your balance; do not add `unallocated_usage` to them again.

### Annual plans

Annual periods include a `monthly` array with twelve buckets anchored to the billing start. For a January 16 start, the first bucket covers January 16–February 16, the second February 16–March 16, and so on. Empty buckets contain zeros.

Each bucket has `year`, `month`, `start_date`, `end_date`, `request_count` and `credits_used`. The year and month identify the bucket's start; the exact timestamps define its boundaries. Monthly totals include pending charges, and refunds adjust the original bucket. The bucket totals plus `unallocated_usage` equal the period totals.

Monthly billing periods omit `monthly`; their totals cover the whole billing period. See the annual response example in the [endpoint reference](/api-reference/usage/get-billing-period-usage).

## Authentication

Use your API key in the `Authorization` header. The v2 usage endpoint also accepts a verified Meer portal JWT for a user with active organization membership when portal access is enabled. Both methods return that account's usage; there is no customer-selection parameter.

A missing key or invalid, expired or unverified portal JWT returns `401`. An invalid or revoked API key, or a portal identity without active organization membership, returns `403`. `GET /periods` uses API-key authentication.

## Existing integrations

`GET /usage_stats` remains available with its original lifetime `customer_name`, `total_requests`, calendar `monthly` and `by_country` response. It has no billing-period envelope or pagination.

When moving to v2, read totals from each `data` item and follow `next_cursor` to retrieve older periods. Do not treat v2's annual `monthly` buckets as calendar months, or assume that a monthly billing period has a `monthly` array.
